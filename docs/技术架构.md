# Mino 技术架构

以 [Kaku](https://github.com/tw93/Kaku)（WezTerm 系）为视觉与交互基准的 macOS 终端，在此之上提供可视化面板（SFTP / 工作区 / AI）与 SSH、SFTP 能力。Rust workspace，两个 crate：

- **`mino-core`**：纯引擎（终端会话 / SSH / SFTP / 配置 / AI 客户端 / Shell 集成 / 更新器），**禁止依赖 egui**
- **`mino-app`**：egui 应用（窗口、渲染、交互）

## 技术选型

| 组件 | 选型 | 理由 |
|---|---|---|
| GUI | eframe / egui 0.36 + wgpu | 原生轻量，macOS 走 Metal；终端行网格自管 GPU 提交 |
| 终端内核 | alacritty_terminal 0.26（vte 解析） | 生产级 VT 仿真 + PTY（Alacritty 自用同一内核） |
| SSH / SFTP | russh 0.62 + russh-sftp 2.4（ring 后端） | 纯 Rust 无 C 依赖（默认 aws-lc-rs 换成 ring） |
| HTTP | ureq 3 | 应用内更新（releases.atom）与 AI 客户端（SSE 流式）共用 |
| 配置 | serde + toml | `hosts.toml` / `known_hosts.toml` / `assistant.toml` / `snapshot.toml` |
| 文件对话框 | rfd 0.15 | 原生选择面板 |
| 剪贴板 / 图片 | arboard 3.6（image-data）+ image 0.25（仅 PNG） | 图片粘贴与路径 token |
| macOS 原生窗口 | objc2-app-kit | 无边框窗口圆角、背景毛玻璃 |
| UI 测试 | egui_kittest 0.36 + kittest（accesskit） | 渲染级断言与像素校验 |

选型原则：平台能力或成熟开源库优先，自研仅限连接、编排与业务逻辑。

## 核心数据流

### 终端会话（本地与远程统一）

- **本地**：`tty::new` 建 PTY → alacritty `EventLoop` 线程读 → vte 解析 → `Term` 网格；会话在后台线程创建（`pending_local` + 帧内 `poll_local_spawn` 挂载），PTY fork + shell 初始化不堵首帧与 ⌘T
- **远程**：共享 tokio runtime → SSH channel 读 → `Processor::advance` → 同一 `Term`
- 统一接口：`Session { term, writer, resizer, shuttor, is_remote }`（Writer / Resizer / Shuttor 闭包抽象）；本地与远程共用同一输入编码与渲染链路
- **Shell 集成标记**：`mino.zsh` 的输出（OSC 133 A/B/C/D、OSC 7、OSC 9;4）在两条读取路径上嗅探——本地经 `sniffer::pty::SniffingPty`（dup 的 ptmx fd 包装），远程直接在读循环内喂 `OscSniffer`；转成 `SessionEvent::{Cwd, PromptReady, CommandStart, CommandFinished, Progress}`，用于权威工作目录、AI 失败建议（退出码）、标签注意力点、shell 空闲判定
- **写回队列**：本地走 `EventLoopSender`、远程走命令队列（UI 线程非阻塞）；程序触发的终端应答（`PtyWrite`）队列有 64KB 字节上限，超限丢最旧

### 终端渲染

- **行级增量**：每帧持锁取 `Term::damage()` + `reset_damage()`，只重建损坏行；行缓存 `HashMap<网格行号, RowCache{hash, galley, backgrounds}>`——滚动后同一网格行直接命中（滚动只重建滚入的新行）
- **两条渲染路径**（同一套行缓存）：
  - **自管 GPU**（有 wgpu 后端）：每行顶点常驻显存（`terminal_gpu.rs`），行内容不变不重传、滚动只改 uniform、空闲帧零上传；逐行槽位 + 区间分配器，`MAX_ROWS = 256`；图集换代看门狗（尺寸变化或填充率骤降时整屏重建）
  - **egui Shape 回退**（kittest / 无 GPU）：行内容合成单个 `Mesh` 一次性提交，Shape 批量 `Painter::extend`
- **布局对齐**：宽字符（CJK）逐 cell 成段，按双列起点定位（避免字体 advance 与终端列宽累积漂移）；块的制表/方块字形无缝拼接；每帧比对 `pixels_per_point`，缩放变化清空全部缓存
- **resize 节流**：网格即时更新（字不越界），后台通知（SIGWINCH / SSH `window_change`）50ms 合并 + trailing 补发；网格尺寸有最小值钳制（20×4），远端在窗口尺寸变化后的时间窗口内每帧补发，避免极小窗口把远端程序锁死成 1 行

### 终端能力应答与输入编码

- **应答**（程序查询必须回执）：OSC 颜色查询（索引 0-259，先做边界检查；OSC 动态覆盖优先于主题调色板）、文本区尺寸查询、焦点上报（DECSET 1004）、鼠标上报（1000/1002/1003 + SGR 1006）、OSC52 剪贴板、OSC8 超链接
- **同步更新（DECRQM 2026）回「不支持」**：应答出口按任意包内容改写（omp 等会把多个查询混在同一次写入）
- **kitty 键盘协议**：`term::Config { kitty_keyboard: true }` 本地/远程/测试三处同源；订阅 DISAMBIGUATE/REPORT_ALL_KEYS_AS_ESC 后仅 Escape、带修饰的 Enter/Tab/Backspace 与 ctrl/alt 文本键走 CSI-u，方向/Home/End/F-键与无修饰键保持 legacy 编码（`keys.rs`）；Shift+Enter=`ESC[13;2~`、Ctrl+Enter=`\n` 兼容 AI CLI 的换行语义
- **`COLORTERM=truecolor`**：本地与远程会话环境注入（sshd 不放行则静默忽略）

### SFTP

- `connect_sftp` 建立独立 SSH 连接（任务跑在共享 runtime 上，会话存活到 `Shutdown` 命令）
- UI 持 `SftpHandle`（克隆发送端）发命令；后台执行后经 `SftpEvent` 通道回报
- 事件流：`Listed / Progress / Done / Error / Closed`；面板收到事件才 `request_repaint`（事件驱动刷新）
- 传输失败清理半成品：下载失败删本地半成品、上传失败删远端半成品
- 主机名绑定在连接上（多远程标签共存不串台）；列表用 `show_rows` 虚拟化

### 连接生命周期

- **主机密钥校验（TOFU，fail-closed）**：终端与 SFTP 都经 `connect_verified` 校验服务器公钥；首次连接把 `SHA256:base64` 指纹写入 `~/.config/mino/known_hosts.toml`（0600），之后必须一致；读取 / 解析 / 保存失败都拒绝信任（不降级为「首次连接」）
- **SSH 配置**：统一 30s keepalive + 3 次无响应断开；私钥路径自动展开 `~`
- **进程级共享 tokio runtime**（`ssh::shared_runtime()`，上限 8 worker）：远程终端与 SFTP 共用，任务以 `Notify` 等待；runtime 不可用时也把失败事件回传（否则 SFTP 面板永久停留在「连接中」）
- `Session` 实现 `Drop` → 发 `Shutdown` 优雅关闭；本地会话在守护线程延时 300ms 补 SIGKILL，兜底 shell 不响应 SIGHUP 导致的退出阻塞

### 应用内更新

- 版本检查走 `releases.atom`（不受 API 限流），资产直链按 `mino-{版本}-macos-{arm64|x64}.dmg` 构造并流式下载（进度回调）
- 下载失败自动删除半成品 dmg；安装由后台 shell 脚本完成：`hdiutil attach` → 等待主进程退出 → `ditto` 替换 `/Applications/Mino.app`（失败回退 `~/Applications`）→ 重新打开

## 样式与主题（Kaku 基准）

- **两套主题**：Kaku Dark（Aura 系，`#15141b` 底 + 紫光标 `#8e6ad9`）与 Kaku Light（Flexoki 系，米白 `#FFFCF0`），跟随 macOS 系统外观自动切换（可强制深/浅）
- **分层底色**：应用 == 终端 == 标签栏同底（`#15141b`），面板 `surface #1f1d28`、浮层/激活标签 `surface_active #29263c`；文字三阶 `#d5d4d6 / #a8a6ae / #6d6d6d`
- **终端调色板**原样搬 Kaku（含「cyan 与 green 同色」「ANSI black 是浅灰」等取值）；`color_overrides` / `foreground_color_overrides` 覆写表 + `text_min_contrast_ratio = 3.0`；粗体不增亮（换字重族）
- 圆角：控件 `RADIUS_SM = 6`、列表项/标签 `RADIUS_ITEM = 4`；hover 统一为 accent 低透明度叠加
- 解析优先级：SGR 指定 > OSC 动态覆盖（`term.colors()`）> 主题调色板

## 字体

- **等宽主字体**：打包随附 JetBrains Mono 三字重（Regular / Medium / SemiBold，OFL 1.1），按「命名族 × 主题深浅 × 粗体」选择（深色 Regular/Medium、浅色 Medium/SemiBold）
- **符号兜底**：Symbols Nerd Font Mono（私有区图标）+ Menlo（macOS 生僻符号），排在打包字重之后
- **CJK fallback**：PingFang / STHeiti 在后台线程读取（78MB 的 `.ttc` 不阻塞首帧），就绪后以 `FontPriority::Lowest` 增量追加（**不用「克隆定义 + set_fonts」**：跨帧比较会误判吞并）；渲染侧按字体定义指纹在帧开头比对、命中才清行缓存
- **禁止加载 Apple Color Emoji**（192MB 彩色位图字体，ab_glyph 无法解析）
- **Proportional 族**：系统 SF 主 + CJK fallback

## 关键工程约定

- **锁序铁律**：唯一合法顺序是「先终端 `FairMutex<Term>`、后 egui `Context`」；任何反向嵌套都会与 PTY 读线程构成 AB-BA 死锁
- **自管 GPU 回调内绝不触碰 `egui_wgpu::Renderer`**（渲染期持锁，回调内再取锁必死锁）；字体图集绑定只在 UI 线程帧内刷新
- **UI 测试必须串行**：`cargo test --workspace -- --test-threads=1`（并行会争抢主题静态与图形后端，出现假失败）
- **测试隔离**：涉及配置读写的 UI 测试一律 `MinoApp::new_with_config(test_config_path(..))`（`/tmp` 隔离路径），绝不读写用户真实配置
- **配置持久化**：全部 0600 + 原子写（临时文件 + fsync + rename）；`hosts.toml` 解析失败先备份 `.bak` 再按空配置启动并提示，绝不静默清空
- **崩溃日志**：`~/.config/mino/crash.log`（追加写；写失败回落 `/tmp`）；下次启动归档为 `crash.log.1` 并提示路径
- egui 0.36 API 注意：`App::ui` 替代 `update`、`Panel::top/left` 替代 `TopBottomPanel`、`Fonts` 需要 `fonts_mut`、`Event::Key` 无 `text` 字段（Text 是独立事件）

## 构建与验证

```bash
cargo build --release                        # 发布构建（strip debuginfo + thin LTO）
cargo test --workspace -- --test-threads=1   # 单元 + ssh/sftp 集成 + UI 渲染
cargo clippy --workspace --all-targets       # 零警告
cargo fmt --all
```

集成测试需要本地测试 sshd（`scripts/test-sshd.sh start`，127.0.0.1:2222）。自管 GPU 渲染路径在 kittest 默认 harness 下不可用（无 wgpu 后端，自动走 egui 回退），需实机或临时 `.wgpu()` harness 验证。
