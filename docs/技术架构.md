# Mino 技术架构

轻量终端 + SFTP 可视化工具。Rust workspace，两个 crate：

- **`mino-core`**：纯引擎（终端会话 / SSH / SFTP / 配置 / 更新器），**禁止依赖 egui**
- **`mino-app`**：egui 应用（窗口、渲染、交互）

## 技术选型

| 组件 | 选型 | 理由 |
|---|---|---|
| GUI | eframe / egui 0.36 + wgpu | 原生轻量，macOS 走 Metal；终端行网格自管 GPU 提交 |
| 终端内核 | alacritty_terminal 0.26（vte 解析） | 生产级 VT 仿真 + PTY（Alacritty 自用同一内核） |
| SSH / SFTP | russh 0.62 + russh-sftp 2.4（ring 后端） | 纯 Rust 无 C 依赖 |
| 应用内更新 | ureq 3（releases.atom 检查 + dmg 下载） | 轻量 HTTP，不受 GitHub API 限流 |
| 配置 | serde + toml（`hosts.toml` / `known_hosts.toml`） | 人类可读、可手编 |
| 文件对话框 | rfd 0.15 | 原生选择面板 |
| 剪贴板 / 图片 | arboard 3.6（image-data）+ image 0.25（仅 PNG） | 图片粘贴与本地路径 token |
| macOS 原生窗口 | objc2-app-kit（CALayer 圆角） | 无边框窗口整体圆角 |
| UI 测试 | egui_kittest 0.36 + kittest（accesskit） | 渲染级断言与像素校验 |

选型原则：平台能力或成熟开源库优先，自研仅限连接、编排与业务逻辑。

## 核心数据流

### 终端会话（本地与远程统一）

- 本地：`tty::new` 建 PTY → alacritty `EventLoop` 线程读 → vte 解析 → `Term` 网格；会话在后台线程创建（避免 PTY fork + shell 启动堵住首帧），UI 帧内挂载标签
- 远程：共享 tokio runtime → SSH channel 读 → `Processor::advance` → 同一 `Term`
- 统一接口：`Session { term, writer, resizer, shuttor, is_remote }`（Writer / Resizer / Shuttor 闭包抽象）
- 写操作：本地走 `EventLoopSender`，远程走命令队列（UI 线程非阻塞）；终端能力应答（`PtyWrite`）有 64KB 上限，超限丢最旧
- 渲染：UI 锁 `FairMutex<Term>` → 行级增量（`Term::damage()` 收集损坏行 + 行 hash 指纹）→ Galley 缓存 / 行网格顶点缓存

### 终端渲染（两条路径）

- **自管 GPU 路径**（有 wgpu 后端时）：每行顶点常驻显存，行内容不变不重传；滚动只更新 uniform；空闲帧零上传。上限 `MAX_ROWS = 256`，逐行槽位 + 区间分配器
- **egui Shape 回退路径**（kittest / 无 GPU）：行内容合成单个 `Mesh` 后一次性 `Painter::extend` 提交
- 两条路径共用同一套行缓存（按网格行号索引）与宽字符逐 cell 分段布局（CJK 与终端列严格对齐）

### SFTP

- `connect_sftp` 建立独立 SSH 连接（任务跑在共享 runtime 上，会话存活到 `Shutdown` 命令）
- UI 持 `SftpHandle`（克隆发送端）发命令；后台执行后经 `SftpEvent` 通道回报
- 事件流：`Listed / Progress / Done / Error / Closed`
- 传输失败清理半成品：下载失败删本地半成品、上传失败删远端半成品

### 连接生命周期

- **主机密钥校验（TOFU）**：终端与 SFTP 都经 `connect_verified` 校验服务器公钥；首次连接把指纹写入 `~/.config/mino/known_hosts.toml`（0600），之后必须一致；读取 / 解析 / 保存失败时拒绝连接，不降级为重新信任
- **SSH 配置**：统一 30s keepalive（`keepalive_interval`）+ 3 次无响应断开（`keepalive_max`）
- **进程级共享 tokio runtime**：远程终端与 SFTP 共用一份 `LazyLock` runtime（上限 8 worker）
- `Session` 实现 `Drop` → 发 `Shutdown` 优雅关闭；本地会话额外在守护线程延时补 SIGKILL，兜底 shell 不响应 SIGHUP 的情况

### 应用内更新

- 版本检查走 `releases.atom`（不受 API 限流），资产直链按 `mino-{版本}-macos-{arm64|x64}.dmg` 构造并流式下载（进度回调）
- 下载失败自动删除半成品 dmg；安装由后台 shell 脚本完成：`hdiutil attach` → 等待主进程退出 → `ditto` 替换 `/Applications/Mino.app`（失败回退 `~/Applications`）→ 重新打开

## 样式与主题

- **分层背景 token**（`theme.rs::tokens`，默认「深色」主题）：应用 `#0d1112` / 标签栏 `#080b0c` / 面板 `#12191a` / 浮层 `#192122` / 终端 `#090d0d`；文字三阶 `#d9e2df / #a6b4b0 / #677672`；主 accent 终端绿 `#4f9d83`、辅助琥珀 `#c39a5b`
- **hover = accent 低透明度叠加**（16/255 alpha），不用整块提亮；选中/激活态用 accent_soft
- 圆角 `RADIUS_SM = 9`（按钮/输入）/ `RADIUS_ITEM = 7`（列表项/标签）
- **三套主题**：深色（石墨绿）/ 深蓝 / 霓虹，每套含 UI token + 独立终端调色板（16 色）；主题按名称持久化在 `hosts.toml`
- 终端调色板解析优先级：SGR 指定 > OSC 覆盖（`term.colors`）> 主题内置调色板；xterm 256 色固定段查表
- **品牌标记**：黑底圆角 + 白色 `>` + 磷光绿光标块（与应用图标 `assets/icon.png` 同构图）

## 字体

- **等宽主字体**：打包随附 JetBrains Mono 四字重（Regular / Italic / Bold / BoldItalic，OFL 1.1），自带提示符符号（`➜` / `❯` / powerline）
- **符号兜底**：Menlo（仅补生僻符号），排在打包字重之后
- **CJK fallback**：PingFang / STHeiti 在后台线程读取，就绪后增量并入字体系统（启动不被 78MB 的 `.ttc` 阻塞）；禁止加载 Apple Color Emoji（彩色位图字体无法解析）
- **Proportional 族**：系统 SF 主 + CJK fallback

## 关键约定

- **锁序铁律**：唯一合法顺序是「先终端 `FairMutex<Term>`、后 egui `Context`」；任何反向嵌套（持 Context 写锁等终端锁）都会与 PTY 读线程构成 AB-BA 死锁
- **UI 测试必须串行**：`cargo test --workspace -- --test-threads=1`（并行会争抢主题静态与图形后端，出现假失败）
- **配置持久化**：`hosts.toml` / `known_hosts.toml` 均强制 0600 权限、原子写（临时文件 + rename）；`hosts.toml` 解析失败时备份为 `.bak` 后按空配置启动并提示，绝不静默清空
- **测试隔离**：涉及配置读写的 UI 测试一律使用 `MinoApp::new_with_config(test_config_path(..))` 指向 `/tmp` 隔离路径，绝不读写用户真实配置
- **崩溃日志**：`~/.config/mino/crash.log`（追加写；Finder 启动时 stderr 无人接收）；下次启动归档为 `crash.log.1` 并 toast 提示路径
- egui 0.36 API 注意：`App::ui` 替代 `update`、`Panel::top/left` 替代 `TopBottomPanel`、`Fonts` 需要 `fonts_mut`、`Event::Key` 无 `text` 字段（Text 是独立事件）
