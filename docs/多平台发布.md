# Mino 多平台发布

## 触发方式

推荐推送 `v<主>.<次>.<补丁>` 标签（也是唯一能保证版本一致的方式）：

```bash
git tag v1.1.2
git push origin v1.1.2
```

也可在 Actions 页手动 **Run workflow**，但**必须填写要发布的 tag**（例如 `v1.1.2`，且该 tag 必须已存在）。

发布门禁（workflow 第一步校验，任一不符直接失败）：

- tag 形如 `vX.Y.Z` 且仓库中已存在
- `Cargo.toml` 的 `[workspace.package] version` 与 tag 去掉 `v` 完全一致
- `CHANGELOG.md` 存在对应的 `## [X.Y.Z]` 段落（Release 正文即由该段落提取）

## 产物

| 平台 | 产物 | 构建方式 |
|---|---|---|
| macOS Apple Silicon | `mino-<版本>-macos-arm64.dmg` | macos-latest（原生 ARM） |
| macOS Intel | `mino-<版本>-macos-x64.dmg` | macos-15-intel（官方 Intel runner） |

- 版本号取自 tag（`v1.1.2` → `1.1.2`）
- 每个平台另上传 `mino.icns`；Release 正文由 `scripts/release-notes.sh` 从 `CHANGELOG.md` 提取对应版本段落
- 测试策略：UI 测试（egui_kittest）只在 **Intel runner** 跑（Apple Silicon runner 的图形环境可能挂起，故限时失败）；功能回归另由 CI（Ubuntu）覆盖

## 本地预览打包（macOS）

```bash
cargo build --release
./scripts/package-macos.sh 1.1.2 arm64
# 产出 target/release/mino-1.1.2-macos-arm64.dmg 与 Mino.app
```

打包脚本逻辑：生成图标（`scripts/make-icon.swift`：黑底圆角渐变 + 白色 `>` + 磷光绿光标块，与应用内品牌标记同构图）→ 组装 .app bundle（Info.plist 含 `LSMinimumSystemVersion 12.0`、文件夹访问用途说明，附 ad-hoc 签名）→ 组装 dmg（内含 `Mino.app` 与 **Applications 快捷方式**，本机打包时自动美化图标布局）→ `hdiutil` 制作 dmg。

## macOS 安装后提示「已损坏」

未公证导致（开源项目未配置 Apple 开发者签名，构建已附 ad-hoc 签名）。解除隔离：

```bash
xattr -cr "/Applications/Mino.app"
```

然后右键 → **打开**。

## 平台支持

**仅支持 macOS 12+**（Apple Silicon + Intel）。CI 在 Ubuntu 上做构建 / 测试 / 静态检查（不产出 GUI 产物）。

SSH 库（russh）使用 ring 后端（纯 Rust，无 C 依赖）。

## 自动更新

- 应用启动后自动检查 GitHub Releases 最新版本（`mino-core::updater`，ureq 轻量 HTTP）
- 检查逻辑：请求 `github.com/yqstart/mino/releases.atom`（Atom feed，不受 API 限流影响），解析首个 `<entry>` 取最新 tag，语义化版本比较
- **应用内一键更新**：按当前架构（arm64/x64）构造 dmg 直链下载（进度回调）→ 后台脚本 `hdiutil` 挂载 → 等待主程序退出 → `ditto` 替换安装到 `/Applications/Mino.app`（失败回退 `~/Applications`）→ 自动重启
- 手动检查：应用内「设置」→「关于」→「检查更新」

## 维护者侧说明

- 工作流文件：`.github/workflows/release.yml`（发布）、`ci.yml`（push main / PR：构建 + 测试 + clippy + fmt）
- 网络集成测试（ssh/sftp 真实链路）需要本地测试 sshd：`./scripts/test-sshd.sh start`（127.0.0.1:2222，可用 `MINO_TEST_PORT` 改端口）
- 发布前建议本地过一遍：`cargo test --workspace -- --test-threads=1 && cargo clippy --workspace --all-targets -- -D warnings && cargo fmt --all --check`
- 发布流程三件套必须一致：`Cargo.toml` 版本 == tag 去 `v` == `CHANGELOG.md` 顶部段落；**先在 `main` 合并代码再打 tag**，禁止在功能分支上打 tag 发布
